6. УЧЕБНЫЕ ТЕКСТЫ. Арабский — всегда с полными огласовками. Прилагательные — парами антонимов (كَبِيرٌ ≠ صَغِيرٌ). Предложение заканчивается точкой, словосочетание — многоточием. Не используй темы, которые ещё не пройдены (список пройденных тем — в метаданных курса).
7. ЯЗЫКИ. Локали: uz (по умолчанию, адрес «/»), ar, ru, en; порядок в переключателе — Oʻzbekcha · العربية · Русский · English. Арабский интерфейс (справа налево) — с самого начала: вёрстка только на логических CSS-свойствах (margin-inline-*, padding-inline-*, inset-inline-*, text-align: start), dir=rtl на <html> у ar, иконки направления зеркалятся. Каждая новая строка интерфейса сразу создаётся во всех четырёх локалях (uz, ar, en — со статусом auto, пока автор не вычитал). Узбекский — латиницей; буквы oʻ и gʻ пишутся с ʻ (U+02BB), апостроф (тутуқ белгиси) — ʼ (U+02BC); переводить по смыслу, а не калькой с русского. Страница без перевода на локаль: оформление этой локали, содержание на исходном языке с плашкой, canonical на исходную страницу, без hreflang.

6. Не выдумывай: арабские слова, формы и вопросы — только из `data/`; ошибку в данных не исправляй молча, а помечай и спрашивай. Ссылки в коде «CLAUDE.md §N» (N = 0.1, 1–11, 13–16) читай как `docs/PRODUCT_SPEC.md §N`.

## Безопасность и данные
- **Секреты** (пароль БД, `service_role`, ключи API, токены) — никогда в код, чат, логи, коммиты. Во фронтенде только `PUBLIC_SUPABASE_URL` и публичный ключ `anon`/`publishable`. Нашёл секрет в истории — сообщи немедленно.
- Всё общение с базой — только через RPC `SECURITY DEFINER`; прямого доступа к таблицам нет (RLS включена). У новой функции — `set search_path`, проверка токена/роли внутри, явные `grant`/`revoke`; **добавь строку в таблицу `expect` теста `supabase/tests/40_hardening_test.sql`**.
- Только псевдонимы учеников; настоящие имена — у преподавателя в браузере. Списки имён нигде публично не показываются. Не показывать студентам чужие ошибки и «антирейтинги».
- Пользовательский текст в `innerHTML` — только через `esc()`/`wrapAr()`. Без `onclick="…"` и новых внешних доменов; внешние скрипты не добавлять.
- **Запрещено без явного согласия заказчика:** удалять данные, страницы и ветки; перезаписывать историю; менять production-настройки, DNS и рабочий Supabase; запускать миграции; деплоить; сливать PR.
- Рискованное изменение: сначала риск, план, файлы/системы, как проверить и как откатить; дождаться «да».

## База данных и миграции
- Схема меняется **только** файлами `supabase/migrations/000N_*.sql` (следующий свободный номер — **0005**). Прямых правок схемы в панели Supabase нет.
- Миграцию запускает заказчик вручную в Supabase SQL Editor **до** слияния PR; скажи об этом прямо. Не запускай SQL в рабочем Supabase без явного разрешения (чтение метаданных — только по отдельной просьбе). Для PR с SQL — отдельная независимая проверка.

Пустой раздел показывает «Скоро», на главной честно: «Материалы добавляются постепенно».
