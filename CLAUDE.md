## 1. Цель

Публичный сайт для изучения арабского языка с русскоязычным интерфейсом. Позже — узбекский и английский.

**Для всех посетителей:**
- главная страница;
- разделы: слова (карточки), викторины, тесты, упражнения, грамматика (памятки), тексты для чтения;
- всё открыто без регистрации; прогресс гостя хранится на его устройстве.

**Для зарегистрированных:**
- прогресс сохраняется в облаке и доступен на любом устройстве;
- личный кабинет «Мой прогресс».

**Для классов (группы преподавателя):**
- студент входит в класс по коду класса + своему коду + ПИН, email не нужен;
- преподаватель видит подробную аналитику: всё, что было в прототипе панели, и больше (раздел 6.6).

**Курсы:**
- упорядоченные подборки заданий: «Арабский, 2 курс ТГУВ — семестр 1», позже «Начальный курс для всех» и т. д.;
- одно задание может входить в несколько курсов.

## 3. Стек — решение и причины

- **[Astro](https://astro.build)** — генератор статических сайтов. Каждая страница (раздел, набор слов, викторина, памятка) собирается в готовый HTML. Почему:
  - это важно для поиска в Google и скорости публичного сайта;
  - интерактив (карточки, викторины, панель) подключается «островами» (islands) на TypeScript, допустим Preact;
  - встроенные **Content Collections** — контент как JSON/Markdown со схемами;
  - встроенная **i18n-маршрутизация**: `defaultLocale: 'ru'`, позже `uz` и `en`, с запасным языком (`fallback`) ([Astro i18n](https://docs.astro.build/ar/guides/internationalization/));
  - официальный деплой на GitHub Pages через Actions ([Astro → GitHub Pages](https://docs.astro.build/en/guides/deploy/github)).
  - Режим: `output: 'static'`; динамика — только на клиенте через Supabase.
- **Supabase** (Postgres + Auth + RPC + RLS) — аккаунты, классы, прогресс, аналитика. Отдельного сервера нет: логика доступа — в SQL-функциях и RLS.
  - Бесплатный тариф на 2026 год: 500 МБ базы, 50 000 активных пользователей в месяц, **проект засыпает после 7 дней без активности** ([источник](https://automationatlas.io/answers/supabase-free-tier-limits-2026/); перед запуском сверить с supabase.com/pricing). Отсюда GitHub Action keep-alive раз в 3 дня.
  - Когда сайт станет большим, заказчик решит, переходить ли на платный тариф. Схема не должна от этого зависеть.
- **Поиск по сайту:** [Pagefind](https://pagefind.app) (статический индекс после сборки). Проверь, как он работает с арабским; если плохо — свой небольшой индекс по словарю.
- **PWA** (установка на телефон, офлайн для карточек) — этап 7. Архитектура должна этому не мешать.
- **Тесты:** Playwright (e2e, мобильный вьюпорт 360 px), проверки SQL (pgTAP или скрипты на локальном `supabase start`), Lighthouse CI.
- **Шрифты:** Amiri для арабского (самостоятельно размещённые woff2, без зависимости от Google Fonts), системный шрифт без засечек для кириллицы.
- **Без трекеров** (Google Analytics и т. п.). Статистика — только своя, из Supabase, для вошедших. Для общего числа посещений позже можно взять что-то без cookies — обсудить с заказчиком.

## 5. Модель данных (черновик — доработай)

Принцип: **один «ученик» (learner)** — это либо пользователь с email, либо ученик класса с ПИН. Весь прогресс ссылается на `learner_id`.

```sql
create table profiles (user_id uuid primary key references auth.users, display_name text,
  role text default 'user' check (role in ('user','teacher','admin')), created_at timestamptz default now());

create table classes (id serial primary key, teacher_id uuid references auth.users, name text, year text,
  join_code text unique,        -- например 'TSU2-25'; вводится учеником
  course_key text,              -- курс по умолчанию
  pseudonym_mode boolean default true, archived boolean default false);

create table learners (id serial primary key,
  user_id uuid unique references auth.users,          -- для пользователей с email
  class_id int references classes(id),                -- для учеников класса
  code text, pin_hash text,                           -- ученик класса: код + crypt(pin)
  nickname text not null, display_name text,          -- display_name = NULL в режиме псевдонимов
  sex char(1) check (sex in ('м','ж')), active boolean default true,
  unique (class_id, code));
create table class_members (class_id int references classes, learner_id int references learners, primary key (class_id, learner_id));
create table pin_tokens (token uuid primary key default gen_random_uuid(), learner_id int, expires_at timestamptz);
create table login_fails (class_id int, code text, at timestamptz default now());

create table activities (key text primary key, kind text, title text, level text, topics text[]);  -- зеркало src/content

create table card_state (learner_id int, deck text, word_key text, n int, ok int, bad int, box smallint, last_step int,
  updated_at timestamptz, primary key (learner_id, deck, word_key));
create table card_steps (learner_id int, deck text, step int, primary key (learner_id, deck));
create table answers (id bigserial primary key, learner_id int, activity text, item_key text, theme text, mode text,
  direction smallint, correct boolean, box_after smallint, answer_ms int, client_id text, created_at timestamptz,
  unique (learner_id, client_id));
create table visits (id text primary key, learner_id int, activity text, started_at timestamptz, ended_at timestamptz,
  active_sec int, items int, ok int, bad int, device text);
create table quiz_attempts (id uuid primary key, learner_id int, class_id int, quiz text, points int, correct int, total int,
  time_sec int, level text, created_at timestamptz default now());
create table quiz_answers (attempt_id uuid references quiz_attempts, q_id int, section text, question text, answer text,
  correct_answer text, ok boolean, sec real);
create table card_tests (id uuid primary key, learner_id int, deck text, correct int, total int, time_sec int, created_at timestamptz);
```

**Доступ:**
- RLS на всём.
- Пользователь с email видит и пишет только своё (`learner.user_id = auth.uid()`).
- Ученик с ПИН работает только через RPC `SECURITY DEFINER` с токеном: `class_login(join_code, code, pin)`, `pin_sync(token, payload)`, `pin_quiz_submit(token, payload)`.
- Преподаватель видит только учеников своих классов: представления и RPC отчётов.
- Защита ПИН: 5 ошибок за 10 минут блокируют код. ПИН — только хэш (`pgcrypto`).
- `teacher_set_pin` возвращает новый ПИН один раз.
- **Гости:** прогресс в `localStorage`. При входе или регистрации — предложение перенести прогресс в аккаунт (слияние по большему `step`).
- **Объём:** подробные `answers` пишутся только для учеников классов и пользователей с включённой опцией «сохранять подробную статистику». Иначе — только `card_state` и итоги. Так база не переполнится, когда сайт станет публичным.

### 6.2 Вход и кабинет
- `/login`: email (magic link или пароль) и вкладка «Я из класса»: код класса, мой код, ПИН, галочка «запомнить на этом телефоне».
- Офлайн: если устройство уже входило, ответы копятся в очереди и отправляются при появлении сети. Дубликаты отсекаются по `client_id`.
- `/me`: прогресс по наборам, курсам и викторинам, трудные слова, история.

### 6.3 Карточки слов (эталон — `legacy/kartochki_100_slov.html` и `legacy/templates/tpl_cards.html`)
- **Уровни (box):**
  - 0 — новое;
  - 1 — не знает или ошибся;
  - 2 — вспоминает;
  - 3–4 — знает;
  - 5 — выучено.
- **Ответ:**
  - «Знаю» поднимает уровень на 1, но новое слово, которое студент сразу знал, получает уровень 3;
  - «Не знаю» или ошибка ставят уровень 1 и увеличивают `bad`;
  - при «Не знаю» до переворота карточка показывает ответ, следующее нажатие ведёт дальше.
- **Подбор следующего слова:**
  - сначала новые слова; но если есть «созревшие» слова с ошибками (уровень ≤ 1 и прошло не меньше 3 шагов), примерно каждое третье место отдаётся им;
  - иначе — случайный выбор с весом `(6 − box)² × (1 + 0.5 × min(bad, 6))`;
  - если слово было 1 шаг назад, вес ×0.02; если 2–3 шага назад — ×0.3;
  - одно и то же слово не выпадает дважды подряд.
- **Тест «20 вопросов»:**
  - вопросы выбираются по тем же весам, новые слова получают вес 12;
  - направления чередуются;
  - из 3 неверных вариантов 2 берутся из той же темы.
- **Фильтры:** «Все слова», «Только трудные», темы. Направления: ар→рус, рус→ар, вперемешку.
- **Вкладки:** «Мои трудные слова», «Рейтинг».
- **Активное время:** +5 секунд каждые 5 секунд, если вкладка видна и последнее действие было меньше 60 секунд назад. Пауза больше 30 минут начинает новый визит.

### 6.4 Викторины (эталон — `legacy/templates/quiz_tpl.html`, `legacy/viktorina_*.html`, генератор `legacy/templates/make_quiz.py`)
- Сохранить поведение прототипа:
  - разделы F/V/G/E (понимание, слова, грамматика, исправление ошибок) с планом вопросов;
  - каждому студенту свой случайный набор вопросов;
  - таймер на вопрос; очки `500 + 500 × остаток_времени / лимит`;
  - уровни;
  - после викторины — разбор своих ответов;
  - панель с текстом урока (`PARA`) и аудирование (`LIS`, в пробном экзамене).
- Гость проходит викторину без сохранения в облако. Вошедший — с сохранением. Таблица лидеров и табло показывают результаты только в рамках класса.
- Живая таблица для проектора: `/board/<quiz>/?class=<код>&hours=3`. В ней только псевдонимы, лучший результат каждого, автообновление каждые 5 секунд.

### 6.6 Панель преподавателя `/teacher` (эталон — `legacy/panel_uchitelya.html`, расширить)
- Выбор класса вверху; все показатели — по выбранному классу и периоду.
- Администратор дополнительно видит общую статистику сайта: число пользователей и самые популярные и самые трудные задания по всем пользователям.
- **Общая картина:** кто занимался, минуты, ответы, точность, входы.
- **Номинации** (по выбранному периоду и активности):
  - ⏱ время; 📚 выучено слов; 🎯 точность (от 50 ответов); 📅 дни; 🔁 входы;
  - 🧪 тесты карточек; 🏆 викторины; 📈 прогресс за период (прирост выученных слов).
  - Только для учителя: ⚠ «нужна помощь» (низкая точность при достаточном объёме) и 💤 «не занимались».
  - Студентам показываются только положительные номинации.
- **Таблица студентов** с сортировкой; по клику — профиль студента:
  - слова по наборам; темы с долей ошибок; трудные слова;
  - все попытки викторин с разбором ответов;
  - активность по дням.
- **Группа:** трудные слова (сортировка по числу ошибившихся студентов); темы; разделы викторин F/V/G/E; активность по дням недели и часам; последние 30 дней.
- **Сравнение:** диаграмма рассеяния «минуты на карточках ↔ средний % викторин» с коэффициентом корреляции и честной подписью: «n = 19, связь не означает причину».
- **Юноши и девушки:** средние значения с n и предупреждением о малой выборке.
- **Фильтры:** период (неделя, месяц, семестр, год), группа.
- **Экспорт:** CSV и XLSX (сводка, трудные слова, все ответы); страница для печати.
- **Управление:** добавить или деактивировать студента; выдать или сбросить ПИН; «Печать карточек с ПИН» (страница A4, 2 × 5 полосок для разрезания); архивировать год.
- Диаграммы рисовать своим простым SVG/CSS (как в прототипе) или одной лёгкой библиотекой. Подписи на русском.

### 6.7 Рейтинг для студентов
Только положительные номинации, только псевдонимы, кэш на 2 минуты. Студент видит и своё место, даже если он не в топ-10.

### 6.8 Контент — Content Collections
- Каждый тип контента — коллекция со схемой (zod) в `src/content.config.ts`. Общие поля:
  - `key`, `title`, `description` (для поиска и превью);
  - `level` (`A0`, `A1`, `A2`, `B1` …; для текущих материалов — `A1`);
  - `topics[]`, `added` (дата), `source` (откуда материал).
- Типы:
  - **набор слов:** `items:[{a, r, t}]`, где `a` — арабский с огласовками, `r` — русский, `t` — тема; позже поля `uz`, `en`;
  - **викторина:** формат `POOL` + `PARA`, `LIS`, `PLAN` из прототипа;
  - **упражнение:** по типам;
  - **грамматика** и **тексты** — Markdown с фронтматтером;
  - **курс:** `{key, title, audience, items:[{activity, week?, note?}]}`.
- Первый курс: `tsu-2-sem1` — «Арабский язык, 2 курс ТГУВ, семестр 1». В него входят все текущие материалы.
- Добавить материал = положить файл и закоммитить; страница, плитка и поиск обновятся при сборке.
- Схемы описать для заказчика в `src/content/SCHEMA.md` по-русски. Новые материалы будут готовиться в другом чате Claude именно в этом формате.
- Перенести:
  - `data/decks` → `decks`;
  - `data/from_pages` и `data/units` → `quizzes` и `exercises`;
  - `data/dictionary_thematic.json` → `/dictionary`.
- Генератор викторины из урока (`legacy/templates/make_quiz.py`) переписать на TS: `npm run make-quiz -- unit10`.

### 6.9 Грамматика и тексты
Раздел создать сразу, даже если в нём пока 1–2 страницы. Памятки у заказчика лежат в Word: прилагательное и определение, нисба, двупадежные имена, предлоги, слитные местоимения, изафа. Их перенос — отдельная задача на потом; Markdown подготовят в другом чате. Формат страницы:
- заголовок;
- правило;
- таблицы с арабским справа налево;
- примеры;
- ссылки на связанные упражнения и викторины.

### 6.10 Языки интерфейса
- Все строки интерфейса — в `src/i18n/ru.ts`, никакого текста прямо в компонентах.
- Сейчас только `ru`. Структура готова к `uz` и `en` (Astro i18n, `prefixDefaultLocale: false`, `fallback` на `ru`).

## 7. Правила оформления и контента (обязательны)

- Весь интерфейс для студентов — **на русском**. Арабский — справа налево (`dir="rtl"`), шрифт Amiri, крупно.
- Дизайн публичного сайта: спокойный, современный, не шаблонный; логотип — надпись «الأُنْمُوذَجُ» шрифтом Amiri. Учебные страницы (карточки, викторины) могут сохранить яркий градиентный стиль прототипов.
- Палитра: бирюзовая гамма (`#1D5C63`, `#2A9D8F`), акценты `#FFD54F` и коралловый `#E76F51`. Фон студенческих страниц — градиент бирюзовый → фиолетовый (`#1D5C63 → #2B1055`), как в прототипах.
- Прилагательные всегда даются парами антонимов: `كَبِيرٌ ≠ صَغِيرٌ`. Знак `≠` не должен отрываться от слов при переносе (неразрывные пробелы).
- Формы — с огласовками, с множественным числом (включая редкие формы), как в `data/`.
- В арабских ячейках стрелка `←`, а не `→`.
- Предложение заканчивается точкой, словосочетание — многоточием.
- Сайт должен работать с телефона: ширина 360 px, нет горизонтальной прокрутки, кнопки ≥ 44 px.
- Тексты ошибок и подсказок — дружелюбные; никаких публичных «антирейтингов».

---
- **SEO:** у каждой страницы — уникальные `title` и `description`, Open Graph, `sitemap.xml`, `robots.txt` (`/teacher`, `/me`, `/board` — `noindex`). На страницах заданий — разметка `schema.org/Quiz` или `LearningResource`, где уместно.
- **Доступность:** контраст AA, фокус с клавиатуры; `lang="ar"` и `dir="rtl"` на каждом арабском фрагменте.


## 8. Приватность и правовые вопросы

- **Публичный сайт с аккаунтами** — нужна страница «Конфиденциальность»: какие данные собираются, зачем, как удалить. Кнопка «удалить мой аккаунт и данные» в `/me`. Черновик текста подготовь, заказчик утвердит.
- **Закон Узбекистана:** ст. 27-1 Закона «О персональных данных» (с 15.04.2021) требует хранить персональные данные граждан Узбекистана на серверах в Узбекистане ([Mondaq](https://mondaq.com/data-protection/1197754/the-law-on-personal-data-has-been-amended)). У Supabase серверов там нет. Поэтому:
  - собирать **минимум**: email (для входа), псевдоним, пол — только у учеников классов и только для статистики;
  - **решение заказчика: хранить только псевдонимы.** Классы работают в режиме псевдонимов: настоящие имена хранятся у преподавателя в браузере (CSV → IndexedDB), в базе — только код и псевдоним;
  - заказчик уточняет вопрос у юристов ТГУВ. Если потребуется хранение в Узбекистане — переносимость обеспечена (Postgres, стандартный SQL, без привязки к закрытым функциям).
- **Несовершеннолетние:** в публичной регистрации — галочка «мне 16 лет или больше, либо у меня есть согласие родителей». Формулировку утверждает заказчик.
- Сырые события хранить ограниченное время (например, 2 года). Затем — агрегаты.

## 11. Чего не делать

- Не выдумывать арабские слова, формы и вопросы: только `data/`. Сомнительные формы (если найдёшь ошибку) — пометить и спросить заказчика.

- Не добавлять трекеры, аналитику Google и т. п.
- Не делать функции, завязанные только на одну группу (например, «19» в коде): всё через классы и курсы.
- Не публиковать контакты, кроме утверждённых в 0.1.
