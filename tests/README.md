# Тесты

## База данных (`supabase/tests/`)

Нужен локальный PostgreSQL 15+ (проверено на 17). Эти же шаги на каждом PR выполняет задание `sql` в `.github/workflows/checks.yml` (миграции берутся перебором `supabase/migrations/*.sql`). Оно проверяет, что миграции применяются и SQL выполняется без ошибок. Все четыре теста (10, 20, 30, 40) сами сравнивают результаты с ожидаемыми и падают при расхождении, а в конце печатают свой маркер «passed»; задание требует маркер у каждого. `10_test.sql` (вход по ПИН, блокировка после 5 ошибок, синхронизация, отчёт учителя) в конце печатает «core tests passed»; ПИН-коды и токены он не печатает.

```bash
createdb t1
psql -d t1 -f supabase/tests/00_supabase_stub.sql      # имитация auth.users, auth.uid(), ролей anon/authenticated
psql -d t1 -c "insert into auth.users(email, created_at) values ('teacher@x', now() - interval '1 day'), ('other@x', now())"
psql -d t1 -v ON_ERROR_STOP=1 -f supabase/migrations/0001_init.sql
psql -d t1 -v ON_ERROR_STOP=1 -f supabase/migrations/0002_quizzes.sql
psql -d t1 -v ON_ERROR_STOP=1 -f supabase/migrations/0003_mock_exits.sql
psql -d t1 -v ON_ERROR_STOP=1 -f supabase/migrations/0004_hardening.sql
psql -d t1 -f supabase/tests/10_test.sql       # вход, блокировка, синхронизация, отчёт учителя; в конце — «core tests passed»
psql -d t1 -f supabase/tests/20_quiz_test.sql   # викторины; в конце печатает «quiz tests passed»
psql -d t1 -f supabase/tests/30_mock_test.sql   # пробные экзамены (выходы из окна); в конце — «mock tests passed»
psql -d t1 -f supabase/tests/40_hardening_test.sql   # права на функции (0004); в конце — «hardening tests passed»
```

Что проверяется:
- вход по ПИН и неверный ПИН;
- блокировка после 5 ошибок;
- синхронизация без дублей;
- устаревшие данные не затирают новые;
- нет прямого доступа к таблицам;
- чужой учитель ничего не видит;
- отчёт, сброс ПИН, роли;
- викторины: сохранение попытки, повтор без дублей, чужой id, рейтинг и табло (только псевдонимы), отчёт и разбор для учителя, чужой учитель ничего не видит;
- права (0004): у всех функций `public` задан `search_path`; кто может вызвать каждую функцию — ровно по таблице в тесте (новая функция без строки в таблице — ошибка); `PUBLIC` не имеет прав ни на одну; `_on_new_user` нельзя вызвать, но триггер создаёт профиль новому пользователю, вставленному ролью без права EXECUTE (как `supabase_auth_admin`);
- пробные экзамены: число выходов из окна сохраняется (мусор → 0, не больше 999), видно ученику и учителю; попытка без `exits` (старая версия сайта) сохраняется как раньше.

## Сквозной тест (`tests/e2e/flow.py`)

1. База `e2e`: шаги выше, но с одним пользователем `teacher@x`.
2. `DB=e2e node tests/mock-supabase.mjs` — мини-эмулятор Supabase на `:8787`. Пароль любого пользователя — `secret123`. Печатает тестовый `ANON`-ключ.
3. Собрать сайт на эмулятор: `PUBLIC_SUPABASE_URL=http://localhost:8787 PUBLIC_SUPABASE_ANON_KEY=<ANON> npm run build`, затем раздать `dist` в корне на `:4322`.
4. `python3 tests/e2e/flow.py` (нужен Playwright для Python).

Сценарий:
1. Учитель создаёт класс и получает ПИН.
2. Ученик занимается как гость, затем входит в класс; прогресс гостя переносится.
3. Ученик занимается карточками, проходит тест, теряет связь и восстанавливает её.
4. На втором устройстве виден тот же прогресс.
5. Срабатывает блокировка ПИН.
6. Рейтинг класса, страница «Мой прогресс», отчёт учителя, настоящие имена (видны только локально).

## Викторины (этап 4)

- `node tests/load_quiz.mjs` (нужен `ANON=<ключ>` из вывода эмулятора) — нагрузочный тест: 19 учеников одновременно отправляют результат, затем повторно. Ожидается 19 попыток, 380 ответов, без дублей.
- `python3 tests/e2e/quiz.py` — сквозной тест на телефоне 360 px: гость проходит викторину без сохранения; ученик проходит урок 10, связь пропадает и возвращается, результат сохраняется один раз; разбор ответов; «Мой прогресс»; аудирование в экзамене; табло проектора; вкладка «Викторины» у учителя, разбор и CSV. Если Playwright не находит браузер: `CHROMIUM=/путь/к/chrome python3 tests/e2e/quiz.py`.
- Пакеты для эмулятора (`pg`, `jsonwebtoken`) и проверки контраста (`axe-core`) — в devDependencies, ставятся `npm ci`.

## Пробные экзамены (`/mock/<экзамен>/`)

- `npm run test:mock` (`tests/mock.mjs`) — быстрая проверка без сборки и браузера, чистые функции `src/lib/mock.ts`: 2000 экзаменов — каждый раз 30 вопросов без повторов, все из pool, за все экзамены встречаются все 400; правильный ответ после перемешивания остаётся правильным и стоит на любом из 4 мест примерно поровну; время от отметки начала, 0:00 ровно в конце, предупреждения за 5 и за 1 минуту; выходы из окна и предел `max_exits`; итоги по темам; попытка для базы (без очков и уровня); испорченное сохранённое состояние отвергается.
- `python3 tests/e2e/mock.py` — телефон 360 px: раздел в меню и на главной, экзамена нет в «Тестах», «Викторинах» и на табло; стартовый экран с правилами; выборка 30 без повторов; режим концентрации (шапка, подвал, крошки скрыты); размер шрифта вопроса, варианты столбиком ≥ 44 px, буквы أ ب ج د; копирование, контекстное меню и «/» закрыты; клавиши 1–4 и ← →; «Отметить», панель номеров; ответы по данным pool — правильный остаётся правильным; выходы из окна (blur, скрытие вкладки, перезагрузка; один уход — один выход); таймер идёт, перезагрузка ничего не сбрасывает, предупреждение за 5 минут, автосдача в 0:00; подтверждение «Завершить» с числом вопросов без ответа; результаты (таблица, сводка по темам, полный список, печать); предел выходов; uz и en без кириллицы; старый адрес `/quizzes/tanal-nahw/` (и `/uz/`, `/en/`) переадресует с параметрами и якорем, без JavaScript — через meta refresh; sitemap и `public/_redirects`. Если запущен эмулятор базы (как для `quiz.py`), ещё: ученик класса сдаёт экзамен, в базе `points = 0`, пустой уровень и `exits`, «Мой прогресс» и панель учителя показывают выходы из окна. Сайт — как для `design.py` (dist в корне на `:4322`).

## Оформление (дизайн 2.0, §14)

- `node tests/contrast.mjs src/styles/tokens.css` — быстрая проверка: все пары цветов (текст/фон) в 4 палитрах × 2 режимах проходят AA. Запускать после любой правки `tokens.css`.
- `python3 tests/e2e/design.py` — каждая страница × 4 палитры × 2 режима × ширина 360 и 1280: контраст AA через axe-core, нет горизонтальной прокрутки, нет ошибок в консоли; плюс окна «Оформление» и «Поиск», вопрос викторины, тест карточек; тема до отрисовки, «как в системе», сохранение выбора; размер текста; поиск (/, Ctrl+K, русский и арабский с огласовками и без); меню и «хлебные крошки». Скриншоты — в `test-results/design/`. `--quick` — 5 страниц вместо 21.
- Сайт для этого теста: `npm run build` (с поиском Pagefind) и раздать `dist` в корне на `:4322` (база не нужна).

## Спряжение глаголов (§13.2)

- `npm run conjugate -- --check` — таблицы `src/content/conjugations/` совпадают с `src/data/verbs.json` (нужен Python 3; пакеты Qutrub ставятся сами в `.venv-conjugate/`).
- `npm run conjugate:lookup` — сверка `verbs.json` со словарём Arramooz: расхождения и неоднозначные глаголы (все они должны быть с пометкой `doubt`).
- `python3 tests/e2e/conjugation.py` — страница глагола на 360 px (13 лиц, переключатель колонок, печать, предупреждение, ссылка на Qutrub), 11 контрольных глаголов задания (огласовка настоящего-будущего), непереходный глагол, крупный шрифт без прокрутки, поиск и фильтр в списке, переход с главной, ссылки из словаря, поиск по сайту.
- Режим «Любой глагол» (Pyodide) этот же тест проверяет, если задан `PYODIDE_DIR` — папка с файлами Pyodide 314.0.7: `npm i --no-save pyodide@314.0.7`, затем положить в `node_modules/pyodide/` колёса `micropip-0.11.1-py3-none-any.whl` и `six-1.17.0-py2.py3-none-any.whl` (`pip download --no-deps micropip==0.11.1 six==1.17.0 -d node_modules/pyodide`) и запустить `PYODIDE_DIR=node_modules/pyodide python3 tests/e2e/conjugation.py`. Запросы к cdn.jsdelivr.net тест отдаёт из этой папки, пакеты Qutrub скачивает с PyPI.

## Языки интерфейса (§15.1)

- `npm run test:i18n` (`tests/i18n.mjs`) — быстрая проверка без сборки: в `uz.ts` и `en.ts` те же ключи, что в `ru.ts`; в каждой строке те же подстановки `{x}` и HTML-теги; узбекская орфография (oʻ, gʻ — знак ʻ U+02BB, тутуқ — ʼ U+02BC, без `'` ‘ ’ и кириллицы); `docs/uz_tekshirish.md` не устарел (иначе `npm run uz-review`).
- `python3 tests/e2e/i18n.py` — все страницы на `/uz/` и `/en/` при ширине 360 и 1280: `<html lang>`, hreflang на три версии и x-default; видимый русский текст есть только в непереведённых материалах (`lang="ru"`, с пометкой «(rus tilida)»); ссылки ведут на тот же язык; нет горизонтальной прокрутки и ошибок в консоли. Плюс переключатель в шапке и подвале, запоминание выбора (русская ссылка открывается на выбранном языке, `?параметры` сохраняются), карточки и викторина на узбекском, поиск на `/uz/`, страница 404 на языке адреса, русская версия без пометок. База не нужна. Сайт — как для `design.py` (dist в корне на `:4322`).
