# Чек-лист безопасности Allimni

Отмечать по ходу. Где написано «Claude», можно попросить Claude Code сделать это в сеансе.

## Перед каждым Merge (Claude проверяет сам, вы смотрите на зелёную галочку)

- [ ] **«Проверки» в PR зелёные.** Это `npm audit`, типы, строки интерфейса, сборка, бюджет веса (size-limit) и Lighthouse. Красный крестик — не мёрджить, прислать снимок Claude.
- [ ] **В изменениях нет секретов.** Нет пароля базы, ключа `service_role` / `sb_secret_…`, ключей `sk-ant-…`, токенов ботов `123456:AA…`. Допустим только публичный ключ `anon` (в нём `"role":"anon"`).
- [ ] **Новая таблица в базе** (файл `supabase/migrations/000N_*.sql`):
  - есть `enable row level security`;
  - есть `revoke all … from anon, authenticated`;
  - доступ к данным — только через функции, которые проверяют, кто вызывает.
- [ ] **Новая функция `SECURITY DEFINER`:**
  - есть `set search_path`;
  - первая строка проверяет право: `_learner(...)`, `_is_teacher()` или `_own_class(...)`;
  - выданы только нужные `grant execute`.
- [ ] **SQL-миграцию запустили в Supabase → SQL Editor до Merge.** Иначе сайт будет вызывать функции, которых ещё нет.
- [ ] **Текст от пользователей** (псевдоним, название класса, ответы) попадает на страницу через `textContent` или `esc()`. Без экранирования в `innerHTML` его подставлять нельзя.
- [ ] **Нет `onclick="…"` и новых встроенных `<script>`.** Обработчики — через `addEventListener`, иначе их запретит CSP. Сборка предупреждает: «встроенные обработчики событий».
- [ ] **Нет новых внешних доменов** (CDN, шрифты Google, счётчики). Если домен действительно нужен — добавить его в `scripts/security/headers.mjs` и объяснить зачем.
- [ ] **Новая зависимость npm:** указаны причина, размер и лицензия (правило 8). GPL/AGPL — только после обсуждения.

## Раз в месяц (10 минут)

- [ ] **Supabase → Advisors → Security Advisor:** нет красных пунктов. Особенно «RLS disabled» и «Function search_path mutable».
- [ ] **Supabase → Authentication → Users:** нет незнакомых аккаунтов. Если открытая регистрация выключена, их и не должно быть.
- [ ] **Supabase → Authentication → Sign In / Providers:** «Allow new users to sign up» выключено. Включать, только когда откроем регистрацию для всех.
- [ ] **GitHub → Security:** нет открытых предупреждений Dependabot и Secret scanning.
- [ ] **GitHub → Actions:** «Будильник базы данных» и «Проверки» зелёные.
- [ ] **Сайт → F12 → Console** на главной, в карточках, викторине и панели учителя: нет строк `[Report Only] Refused…`. Это нарушения CSP, пока они только записываются.

## Раз в семестр / после экзамена

- [ ] Архивировать классы прошлого года (панель учителя). Сбросить ПИН ученикам, которые ушли.
- [ ] Проверить срок хранения данных (CLAUDE.md §8: сырые события — около 2 лет). Старые попытки и ответы — свести в итоги или удалить. Делает Claude отдельной миграцией.
- [ ] Обновить зависимости: `npm outdated`, затем по одной, с проверками.
- [ ] Сменить пароль учителя и администратора, если им кто-то пользовался вместе с вами.

## Если секрет утёк (попал в код, чат, снимок экрана)

1. **Сразу отозвать:**
   - Supabase → Project Settings → API Keys → **Roll** (новый `service_role` / secret key);
   - пароль базы: Database → Reset password;
   - токен бота: @BotFather → `/revoke`.
2. Положить новый ключ в секреты (GitHub → Settings → Secrets, Supabase → Edge Functions → Secrets). **Не в код.**
3. Сказать Claude: он проверит историю git. Удалить коммит из истории мало: старый ключ надо считать известным, поэтому шаг 1 обязателен.

## Если ученик говорит «кто-то вошёл под моим кодом»

Панель учителя → «Ученики и ПИН» → отметить ученика → «Новый ПИН отмеченным». Все старые входы этого ученика сразу перестанут работать.

## Настройки GitHub (один раз, вручную)

- [ ] **Settings → Code security:**
  - **Secret Protection** (сканирование секретов) и **Push protection** — включить; для публичных репозиториев бесплатно;
  - **Dependabot alerts** и **Dependabot security updates** — включить.
- [ ] **Settings → Rules → Rulesets → New branch ruleset** для `main`:
  - «Require a pull request before merging»;
  - «Require status checks to pass» → проверка `checks` (она появится в списке после первого запуска «Проверок»);
  - «Block force pushes».

  Это защитит `main` от случайной прямой отправки.

  **Что изменится для вас:** файлы, загруженные через сайт GitHub (Add file → Upload files), больше не попадут в `main` напрямую. GitHub сам предложит «Create a new branch for this commit and start a pull request»: соглашайтесь, дождитесь зелёной галочки и нажмите Merge.
- [ ] **Settings → Pages → Verified domains** (в настройках аккаунта): подтвердить `allimni.net`.
