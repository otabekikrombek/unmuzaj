## 0. Быстрый старт (читать первым)

**Что это за файл.** Это не код сайта, и **ничего загружать в репозиторий не нужно**. Это «банк промтов»: готовые тексты, которые вы копируете и вставляете в чат с Claude. Сайт переделывает Claude Code (он подключён к вашему репозиторию `unmuzaj`) — по этим текстам, этап за этапом.

**Как делать любой этап (всегда одинаково):**
1. Откройте новый чат нужного типа (колонка «Где запускать» в разделе 2). Один этап — один чат.
2. Скопируйте текст из рамки целиком, вставьте в чат и отправьте.
3. Claude Code работает и в конце присылает отчёт из пяти пунктов.
4. Если в отчёте есть SQL-файл — сначала запустите его в Supabase SQL Editor, затем Create PR → Merge (как вы делали раньше).
5. Проверьте то, что просит отчёт («что мне проверить вручную»). Только потом — следующий этап.

**С чего начать (два готовых файла лежат рядом с этим):**
- `Allimni_START_E0_issledovanie.txt` — вставить в чат этого проекта (в нём есть веб-поиск). Кода нет, результат — отчёт-исследование.
- `Allimni_START_E1_audit_bezopasnost.txt` — вставить в Claude Code в репозитории `unmuzaj`. Он сам запишет общие правила в `CLAUDE.md`, сделает аудит и защиту. Внешний вид и адреса сайта не меняются.

Эти два этапа можно запускать сразу и независимо друг от друга: от вопросов раздела 8 они не зависят.

**Остальные этапы (E2–E9)** лежат ниже, каждый в своей рамке. Когда дойдёте до нужного, можно написать мне: «дай готовый текст этапа E3» — подготовлю его с учётом всего, что уже сделано.

**Порядок:** E1 → E2 и E3 → E4 → E5 → E6 → E7 → E8 → E9 (E8 зависит только от E1 и может идти раньше). Адреса меняем один раз (E3), иначе потеряем то, что Google уже проиндексировал. E0 идёт параллельно и уточняет E2, E4, E5, E9.

**Общие правила** (раздел 3) вставлять каждый раз не нужно: этап E1 записывает их в `CLAUDE.md`, и дальше Claude Code читает их сам.

## 1. Честная оценка ваших идей

Вы просили оценивать критически. Коротко по каждому пункту: что принимаю, что меняю и почему.

**1. Порядок языков: узбекский → арабский → английский → русский. Принято (решение автора).**
Речь о языках страниц сайта. Узбекский главный (адрес «/»): сайт задуман как путь к арабскому языку именно от узбекского. Материалы появятся позже, по мере того как вы их создаёте.
- **Арабский интерфейс с самого начала — довод верный.** Переделывать вёрстку под письмо справа налево, когда сайт уже вырос, дороже, чем заложить её сейчас. Закладываем в E2–E3: только логические CSS-свойства (`margin-inline-start` вместо `margin-left`), `dir="rtl"` на `<html>` у `/ar/`, зеркальные иконки направления, маршруты `/ar/` и файл `ar.json`.
- **Честная оговорка.** Для студента-начинающего арабское меню не снижает барьер: это решение «на вырост» и для арабоязычных гостей. Поэтому курс `tsu-2-sem1` по-прежнему открывается на русском (язык задаётся классом).
- **Страницы без арабского перевода** (материалы вы добавляете постепенно): арабское оформление и содержание на исходном языке с плашкой; canonical — на исходную страницу, в hreflang и sitemap такая страница не входит. Иначе есть риск, что поисковик сочтёт такие страницы дубликатами. Правило описано в E3.
- **Качество арабских строк.** Машинный перевод нельзя выдавать за готовый: статус `reviewed` / `auto`. Вычитываете вы как преподаватель арабского; при возможности — вторая проверка носителем.

**2. Шрифты. Принято в уточнённом виде (решение автора).**
- **Логотип «عَلِّمْنِي» — куфи или сульс.** Делаем SVG-контуром (буквы превращены в кривые): шрифт на странице не нужен, файл маленький. Оговорка: настоящий сульс — работа каллиграфа. Claude Code может превратить в контуры буквы из шрифта (куфи) или оцифровать утверждённый макет, но не нарисовать каллиграфию сам (вопрос 9).
- **Арабские заголовки — куфи или рукъа.** Кандидаты: куфи — Noto Kufi Arabic, Reem Kufi; рукъа — Aref Ruqaa (есть в Google Fonts, лицензия OFL; файл лицензии проверит E2). Предупреждение: рукъа — скоропись с плотной посадкой строк, у многих шрифтов этого стиля огласовки и шадда ложатся неточно или обрезаются. Как с этим у Aref Ruqaa — **не проверено**; E2 протестирует на ваших полностью огласованных заголовках. Если не пройдёт, рукъа остаётся для коротких декоративных надписей, а заголовки — куфи.
- **Основной арабский текст — насх.** Открытые кандидаты: Noto Naskh Arabic, Amiri, Scheherazade New. **«Traditional Arabic»** — шрифт Microsoft (Monotype): поставляется только с продуктами Microsoft (Windows, Office), отдельно не скачивается и не является открытым; условия его использования на сайтах я не проверял. Поэтому свой файл с ним на сайт не кладём. Решение: основной — открытый насх, «Traditional Arabic» указываем только как системный запасной шрифт. В ваших Word-файлах вы можете использовать его как раньше.
- Для узбекского (латиница) и русского шрифты подбираем отдельно, проверяя `ʻ` (U+02BB) и `ʼ` (U+02BC).
- Решение по заголовкам и тексту — по тесту на ваших реальных текстах (E2), а не по первому впечатлению.

**3. «Как главная страница Claude». Берём принципы, не копируем.**
Берём: много воздуха, тёплый нейтральный фон, один центральный элемент, спокойная палитра, серифные заголовки. Не берём чужие шрифты, логотип и макеты. Центральным элементом сделаем поиск по сайту — аналог поля ввода у Claude, но по делу: слова, глаголы, уроки.

**4. Убрать «Учить слова» и «Я из класса», содержание отдельно. Принимаю с оговоркой.**
Если спрятать всё за начальным экраном, новому посетителю станет дальше до контента. Поэтому оставляем одну заметную кнопку «Содержание». Эффект измеряем без cookies: доля посетителей, дошедших до первого урока.

**5. Гость / студент / преподаватель. Принимаю.**
Ваша логика верна. «Гость» — это не вход, а продолжение без аккаунта (прогресс хранится в браузере). «Студент» — вход по коду класса, «Преподаватель» — панель.

**6. «Урок 1», «Урок 2», слова при своём тексте. Принимаю.**
Добавляем три защиты: прогресс учеников не ломаем (поле `a` и `key` неприкосновенны), адреса не ломаем (301-редиректы), ключи к ДЗ на публичный сайт не выкладываем. Плюс проверка при сборке, что урок не использует непройденные темы (ваше правило 4).

**7. Спряжение: скрыть список, искать любой глагол. Принимаю.**
Это правильный интерфейс. Заодно исправим причину, по которой не находятся глаголы II–X пород (диагностика в E6).

**8. Подписи Qutrub, Arramooz, Pyodide. Принято: переносим на «Лицензии и источники», не удаляем.**
Это не вопрос вкуса. По данным их репозиториев Arramooz распространяется по GPL, и Qutrub, по вашему тексту, тоже. Pyodide загружает код в браузер посетителя, то есть он распространяется. GPL требует сохранить уведомления об авторстве и дать доступ к исходному коду. Решение: со страницы спряжения убрать, перенести на страницу «Лицензии и источники» (ссылка в подвале каждой страницы). Совместимость лицензий всего сайта стоит проверить у юриста, я не юрист.

**9. Предупреждения о проверке. Принято в вашей формулировке.**
Три красных сообщения убираем. У результата одна маленькая нейтральная метка: «проверено ✓» (глагол из вашего списка) или «требует проверки — сайт может ошибаться» (автоматический расчёт). Qutrub — генератор по правилам, для редких глаголов он может ошибаться, поэтому честная метка нужна: это научная честность и ваше правило о пометке сомнительных форм.

**10. Pyodide (Python в браузере). Требует замера.**
По данным репозитория Pyodide, `pyodide.asm.wasm` весит около 9 МБ без сжатия и около 2,7 МБ с brotli, плюс стандартная библиотека около 2,5 МБ. Для «лёгкого» сайта и мобильного интернета это много. Решение в E6: предрасчёт таблиц на этапе сборки, а Pyodide — запасной путь, загружаемый только по требованию.

**11. «Обезопасить». Обязательно.**
Самые вероятные слабые места такого стека: политики доступа в Supabase (RLS), подбор 4-значного ПИН, правильные ответы контрольных в открытом JSON, отсутствие заголовков безопасности. Разбираем в E1 и E8.

**12. «Международный уровень». Да, но с приоритетами.**
Проект ведёт один преподаватель. Для международного уровня критичны качество материала, аудио, доступность, скорость и перевод. На старте не нужны: ИИ-помощник, форум, мобильные приложения, рейтинги. Подробно в разделе 7.

Не используй темы, которые ещё не пройдены (список пройденных тем — в метаданных курса).
7. ЯЗЫКИ. Локали: uz (по умолчанию, адрес «/»), ar, en, ru; порядок в переключателе — Oʻzbekcha · العربية · English · Русский. Арабский интерфейс (справа налево) — с самого начала: вёрстка только на логических CSS-свойствах (margin-inline-*, padding-inline-*, inset-inline-*, text-align: start), dir=rtl на <html> у ar, иконки направления зеркалятся. Каждая новая строка интерфейса сразу создаётся во всех четырёх локалях (uz, ar, en — со статусом auto, пока автор не вычитал). Узбекский — латиницей; буквы oʻ и gʻ пишутся с ʻ (U+02BB), апостроф (тутуқ белгиси) — ʼ (U+02BC); переводить по смыслу, а не калькой с русского. Страница без перевода на локаль: оформление этой локали, содержание на исходном языке с плашкой, canonical на исходную страницу, без hreflang.
8. ЗАВИСИМОСТИ. Не добавляй новые без причины; для каждой укажи размер и лицензию.

Арабский текст — насх; «Traditional Arabic» (шрифт Microsoft, не открытый) — только системный запасной, его файл на сайт не кладём. Самохостинг, подмножества woff2, font-display: swap, только шрифты с открытой лицензией.

Формат отчёта в конце этапа
1) что сделано (до 10 строк); 2) замеры «до/после» по бюджету; 3) что мне проверить вручную; 4) SQL-миграции и порядок запуска; 5) что осталось и какие риски.

## 7. Стратегия: путь к международному уровню

**Позиционирование (гипотеза, проверит E0).** Не «ещё один Duolingo для арабского», а точный ресурс: литературный арабский для узбекоговорящих и русскоговорящих, по логике университетского курса «текст → слова → грамматика → упражнения», с корректными огласовками, спряжением и прозрачным научным аппаратом (источники, пометки сомнительных форм). Бесплатных ресурсов с таким сочетанием, вероятно, мало — но это надо подтвердить.

**Принципы**
1. Скорость — это функция: бюджет проверяется в CI.
2. Научная честность: источники, пометки сомнительного, статус перевода.
3. Сначала узбекоговорящий пользователь, затем остальные; арабский интерфейс заложен с первого дня.
4. Приватность по умолчанию: псевдонимы, аналитика без cookies.
5. Одно изменение за раз; не ломать адреса и прогресс учеников.
6. Решения по измерениям, а не по вкусу (шрифты, скорость, поиск).

**Фазы**

| Фаза | Этапы | Результат |
|---|---|---|
| 1. Фундамент | E1, E3 (+E0 параллельно) | Замеры, защита, схема адресов и четырёх языков, редиректы |
| 2. Опыт | E2, E4, E5 | Новый дизайн, главная, структура уроков |
| 3. Язык и инструменты | E6, E7 | Спряжение без ошибок, узбекский на уровне главного языка |
| 4. Доверие | E8 | Честные контрольные, защита данных |
| 5. Масштаб | E9 | SEO, доступность, офлайн, аудио, материалы для преподавателей |

**Метрики успеха:** доля посетителей, дошедших до первого урока; возврат через 7 дней; число уроков с аудио; доля `reviewed` узбекских страниц; показы и клики по запросу «allimni» и число проиндексированных страниц по языкам (Search Console); Lighthouse и Core Web Vitals; число находок безопасности.

**Риски**

| Риск | Что делаем |
|---|---|
| Потеря позиций в поиске при смене адресов | Один раз определить схему (E3), 301, проверка скриптом, повторная отправка sitemap |
| Падение скорости из-за шрифтов и Pyodide | Бюджет в CI, подмножества шрифтов, предрасчёт спряжения |
| Ошибки машинного перевода | Статус `reviewed` / `auto`, глоссарий, ваша вычитка |
| Лицензии GPL | Страница «Лицензии и источники», юридическая проверка |
| Потеря прогресса учеников | Не менять `a` и `key`; тест на тестовом ученике |
| Перегрузка автора | Этапы малые, одна задача за раз; E9 — бэклог, не план на все пункты сразу |
| Расходы на Claude API | Перевод один раз с кэшем, лимит расходов; ИИ-помощник откладывается |
| Арабский интерфейс с нуля: больше работы в E2–E4 | Логические CSS-свойства сразу; это дешевле, чем переделка позже |
| Страницы `/ar/` без перевода похожи на дубликаты | canonical на исходную страницу, вне hreflang и sitemap (правило E3) |
| Рукъа-шрифт плохо ставит огласовки | Тест в E2 на огласованных заголовках; запасной вариант — куфи |
