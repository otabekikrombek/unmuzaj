## 1. Цель

Публичный сайт для изучения арабского языка с русскоязычным интерфейсом. Позже — узбекский и английский.

**Для всех посетителей:**
- главная страница;
- разделы: слова (карточки), викторины, тесты, упражнения, грамматика (памятки), тексты для чтения;
- всё открыто без регистрации; прогресс гостя хранится на его устройстве.

**Для зарегистрированных:**
- прогресс сохраняется в облаке и доступен на любом устройстве;
- личный кабинет «Мой прогресс».

**Для классов (группы преподавателя):**
- студент входит в класс по коду класса + своему коду + ПИН, email не нужен;
- преподаватель видит подробную аналитику: всё, что было в прототипе панели, и больше (раздел 6.6).

**Курсы:**
- упорядоченные подборки заданий: «Арабский, 2 курс ТГУВ — семестр 1», позже «Начальный курс для всех» и т. д.;
- одно задание может входить в несколько курсов.

## 3. Стек — решение и причины

- **[Astro](https://astro.build)** — генератор статических сайтов. Каждая страница (раздел, набор слов, викторина, памятка) собирается в готовый HTML. Почему:
  - это важно для поиска в Google и скорости публичного сайта;
  - интерактив (карточки, викторины, панель) подключается «островами» (islands) на TypeScript, допустим Preact;
  - встроенные **Content Collections** — контент как JSON/Markdown со схемами;
  - встроенная **i18n-маршрутизация**: `defaultLocale: 'ru'`, позже `uz` и `en`, с запасным языком (`fallback`) ([Astro i18n](https://docs.astro.build/ar/guides/internationalization/));
  - официальный деплой на GitHub Pages через Actions ([Astro → GitHub Pages](https://docs.astro.build/en/guides/deploy/github)).
  - Режим: `output: 'static'`; динамика — только на клиенте через Supabase.
- **Supabase** (Postgres + Auth + RPC + RLS) — аккаунты, классы, прогресс, аналитика. Отдельного сервера нет: логика доступа — в SQL-функциях и RLS.
  - Бесплатный тариф на 2026 год: 500 МБ базы, 50 000 активных пользователей в месяц, **проект засыпает после 7 дней без активности** ([источник](https://automationatlas.io/answers/supabase-free-tier-limits-2026/); перед запуском сверить с supabase.com/pricing). Отсюда GitHub Action keep-alive раз в 3 дня.
  - Когда сайт станет большим, заказчик решит, переходить ли на платный тариф. Схема не должна от этого зависеть.
- **Поиск по сайту:** [Pagefind](https://pagefind.app) (статический индекс после сборки). Проверь, как он работает с арабским; если плохо — свой небольшой индекс по словарю.
- **PWA** (установка на телефон, офлайн для карточек) — этап 7. Архитектура должна этому не мешать.
- **Тесты:** Playwright (e2e, мобильный вьюпорт 360 px), проверки SQL (pgTAP или скрипты на локальном `supabase start`), Lighthouse CI.
- **Шрифты:** Amiri для арабского (самостоятельно размещённые woff2, без зависимости от Google Fonts), системный шрифт без засечек для кириллицы.
- **Без трекеров** (Google Analytics и т. п.). Статистика — только своя, из Supabase, для вошедших. Для общего числа посещений позже можно взять что-то без cookies — обсудить с заказчиком.

## 5. Модель данных (черновик — доработай)

Принцип: **один «ученик» (learner)** — это либо пользователь с email, либо ученик класса с ПИН. Весь прогресс ссылается на `learner_id`.

```sql
create table profiles (user_id uuid primary key references auth.users, display_name text,
  role text default 'user' check (role in ('user','teacher','admin')), created_at timestamptz default now());

create table classes (id serial primary key, teacher_id uuid references auth.users, name text, year text,
  join_code text unique,        -- например 'TSU2-25'; вводится учеником
  course_key text,              -- курс по умолчанию
  pseudonym_mode boolean default true, archived boolean default false);

create table learners (id serial primary key,
  user_id uuid unique references auth.users,          -- для пользователей с email
  class_id int references classes(id),                -- для учеников класса
  code text, pin_hash text,                           -- ученик класса: код + crypt(pin)
  nickname text not null, display_name text,          -- display_name = NULL в режиме псевдонимов
  sex char(1) check (sex in ('м','ж')), active boolean default true,
  unique (class_id, code));
create table class_members (class_id int references classes, learner_id int references learners, primary key (class_id, learner_id));
create table pin_tokens (token uuid primary key default gen_random_uuid(), learner_id int, expires_at timestamptz);
create table login_fails (class_id int, code text, at timestamptz default now());

create table activities (key text primary key, kind text, title text, level text, topics text[]);  -- зеркало src/content

create table card_state (learner_id int, deck text, word_key text, n int, ok int, bad int, box smallint, last_step int,
  updated_at timestamptz, primary key (learner_id, deck, word_key));
create table card_steps (learner_id int, deck text, step int, primary key (learner_id, deck));
create table answers (id bigserial primary key, learner_id int, activity text, item_key text, theme text, mode text,
  direction smallint, correct boolean, box_after smallint, answer_ms int, client_id text, created_at timestamptz,
  unique (learner_id, client_id));
create table visits (id text primary key, learner_id int, activity text, started_at timestamptz, ended_at timestamptz,
  active_sec int, items int, ok int, bad int, device text);
create table quiz_attempts (id uuid primary key, learner_id int, class_id int, quiz text, points int, correct int, total int,
  time_sec int, level text, created_at timestamptz default now());
create table quiz_answers (attempt_id uuid references quiz_attempts, q_id int, section text, question text, answer text,
  correct_answer text, ok boolean, sec real);
create table card_tests (id uuid primary key, learner_id int, deck text, correct int, total int, time_sec int, created_at timestamptz);
```

**Доступ:**
- RLS на всём.
- Пользователь с email видит и пишет только своё (`learner.user_id = auth.uid()`).
- Ученик с ПИН работает только через RPC `SECURITY DEFINER` с токеном: `class_login(join_code, code, pin)`, `pin_sync(token, payload)`, `pin_quiz_submit(token, payload)`.
- Преподаватель видит только учеников своих классов: представления и RPC отчётов.
- Защита ПИН: 5 ошибок за 10 минут блокируют код. ПИН — только хэш (`pgcrypto`).
- `teacher_set_pin` возвращает новый ПИН один раз.
- **Гости:** прогресс в `localStorage`. При входе или регистрации — предложение перенести прогресс в аккаунт (слияние по большему `step`).
- **Объём:** подробные `answers` пишутся только для учеников классов и пользователей с включённой опцией «сохранять подробную статистику». Иначе — только `card_state` и итоги. Так база не переполнится, когда сайт станет публичным.

### 6.2 Вход и кабинет
- `/login`: email (magic link или пароль) и вкладка «Я из класса»: код класса, мой код, ПИН, галочка «запомнить на этом телефоне».
- Офлайн: если устройство уже входило, ответы копятся в очереди и отправляются при появлении сети. Дубликаты отсекаются по `client_id`.
- `/me`: прогресс по наборам, курсам и викторинам, трудные слова, история.

### 6.3 Карточки слов (эталон — `legacy/kartochki_100_slov.html` и `legacy/templates/tpl_cards.html`)
- **Уровни (box):**
  - 0 — новое;
  - 1 — не знает или ошибся;
  - 2 — вспоминает;
  - 3–4 — знает;
  - 5 — выучено.
- **Ответ:**
  - «Знаю» поднимает уровень на 1, но новое слово, которое студент сразу знал, получает уровень 3;
  - «Не знаю» или ошибка ставят уровень 1 и увеличивают `bad`;
  - при «Не знаю» до переворота карточка показывает ответ, следующее нажатие ведёт дальше.
- **Подбор следующего слова:**
  - сначала новые слова; но если есть «созревшие» слова с ошибками (уровень ≤ 1 и прошло не меньше 3 шагов), примерно каждое третье место отдаётся им;
  - иначе — случайный выбор с весом `(6 − box)² × (1 + 0.5 × min(bad, 6))`;
  - если слово было 1 шаг назад, вес ×0.02; если 2–3 шага назад — ×0.3;
  - одно и то же слово не выпадает дважды подряд.
- **Тест «20 вопросов»:**
  - вопросы выбираются по тем же весам, новые слова получают вес 12;
  - направления чередуются;
  - из 3 неверных вариантов 2 берутся из той же темы.
- **Фильтры:** «Все слова», «Только трудные», темы. Направления: ар→рус, рус→ар, вперемешку.
- **Вкладки:** «Мои трудные слова», «Рейтинг».
- **Активное время:** +5 секунд каждые 5 секунд, если вкладка видна и последнее действие было меньше 60 секунд назад. Пауза больше 30 минут начинает новый визит.

### 6.4 Викторины (эталон — `legacy/templates/quiz_tpl.html`, `legacy/viktorina_*.html`, генератор `legacy/templates/make_quiz.py`)
- Сохранить поведение прототипа:
  - разделы F/V/G/E (понимание, слова, грамматика, исправление ошибок) с планом вопросов;
  - каждому студенту свой случайный набор вопросов;
  - таймер на вопрос; очки `500 + 500 × остаток_времени / лимит`;
  - уровни;
  - после викторины — разбор своих ответов;
  - панель с текстом урока (`PARA`) и аудирование (`LIS`, в пробном экзамене).
- Гость проходит викторину без сохранения в облако. Вошедший — с сохранением. Таблица лидеров и табло показывают результаты только в рамках класса.

### 6.6 Панель преподавателя `/teacher` (эталон — `legacy/panel_uchitelya.html`, расширить)

## 8. Приватность и правовые вопросы

- **Публичный сайт с аккаунтами** — нужна страница «Конфиденциальность»: какие данные собираются, зачем, как удалить. Кнопка «удалить мой аккаунт и данные» в `/me`. Черновик текста подготовь, заказчик утвердит.
- **Закон Узбекистана:** ст. 27-1 Закона «О персональных данных» (с 15.04.2021) требует хранить персональные данные граждан Узбекистана на серверах в Узбекистане ([Mondaq](https://mondaq.com/data-protection/1197754/the-law-on-personal-data-has-been-amended)). У Supabase серверов там нет. Поэтому:
  - собирать **минимум**: email (для входа), псевдоним, пол — только у учеников классов и только для статистики;
  - **решение заказчика: хранить только псевдонимы.** Классы работают в режиме псевдонимов: настоящие имена хранятся у преподавателя в браузере (CSV → IndexedDB), в базе — только код и псевдоним;
  - заказчик уточняет вопрос у юристов ТГУВ. Если потребуется хранение в Узбекистане — переносимость обеспечена (Postgres, стандартный SQL, без привязки к закрытым функциям).
- **Несовершеннолетние:** в публичной регистрации — галочка «мне 16 лет или больше, либо у меня есть согласие родителей». Формулировку утверждает заказчик.
- Сырые события хранить ограниченное время (например, 2 года). Затем — агрегаты.

## 13. Новые задачи заказчика (2026-10-13): внешние ресурсы внутри интерфейса сайта

Заказчик хочет, чтобы внешние ресурсы были **встроены в интерфейс сайта**, а не были просто списком ссылок. Общий принцип — **«свой интерфейс + честная ссылка на источник»**:
- не копировать чужие тексты, статьи и PDF к себе: авторское право;
- не встраивать чужие страницы в `iframe`: большинство сайтов это запрещают (`X-Frame-Options`), и это выглядит чужим;
- не «парсить» сайты без открытого API: нарушает их правила, из браузера блокируется CORS и ломается при любом изменении вёрстки.

Использовать: собственные данные, открытые API и открытые библиотеки, официальные встраивания (YouTube), глубокие ссылки на страницу источника.

**Важно про сеть:** в облачной среде Claude Code интернет ограничен пакетными репозиториями. Списки статей, книг и каналов подготавливаются в обычном чате Claude (с веб-поиском) и приходят сюда готовыми JSON-файлами. Сам не придумывай названия, адреса и авторов. Пока JSON нет — пустой раздел с «Скоро».

### 13.1 Слово дня (главная)
- Источник — **свой** словарь и наборы (`src/data/dictionary.json`, `src/content/decks/`). Слово выбирается по дате: одинаковое у всех в течение дня, без повторов, пока не пройдён весь список.
- На карточке:
  - слово с огласовками, перевод, множественное число или пара антонимов (как в данных), тема;
  - кнопка «Послушать» — синтез речи браузера (`speechSynthesis`, `lang='ar'`); если арабского голоса нет, кнопку не показывать;
  - ссылки «Подробнее в Альмаани» (`https://www.almaany.com/ar/dict/ar-ar/<слово без огласовок>/`) и «Викисловарь».
- Почему не брать слово дня с almaany.com: открытого API нет, перепечатка их статей — нарушение правил сайта. Глубокая ссылка решает задачу честно.

### 13.2 Спряжение глаголов — страница `/conjugation/` + поле на главной

  2. **В браузере**: `libqutrub` через Pyodide, загружается только на этой странице. Полностью независимо, но тяжело (несколько МБ) — проверь размер и скорость на телефоне.
  3. **API сайта qutrub.arabeyes.org**: только если у него есть открытый API с разрешённым CORS. Иначе — только ссылка «открыть в Qutrub».

### Лицензии: Qutrub и Arramooz (GPL) — как устроено и почему
- Qutrub (`libqutrub`) и словарь Arramooz (`arramooz-pysqlite`) — © Taha Zerrouki, лицензия GPL. Если их код лежит в нашем репозитории или собран с кодом сайта в одну программу, GPL требует распространять и сайт под GPL. Поэтому **их код в репозиторий не копируем**:
  - при подготовке таблиц пакеты ставятся через pip в `.venv-conjugate/` (папка в `.gitignore`), версии закреплены в `scripts/conjugate/requirements.txt`;

## 14. Дизайн 2.0 (пожелания заказчика, 2026-10-13)

### 14.1 Что просит заказчик
1. **Логически упорядочить всё.** Единая навигация и единые шаблоны страниц; понятно, где ты и куда идти дальше.
2. **Тёмная тема и переключатель.** Варианты «светлая / тёмная / как в системе», выбор запоминается. Арабский текст и таблицы должны читаться в обеих темах (контраст AA).
3. **Несколько цветовых тем** на выбор:
   - «Бирюза» — текущая, по умолчанию;
   - «Лазурит» — синяя;
   - «Пергамент» — тёплая, «книжная»;
   - «Контраст» — для слабого зрения.

   Все цвета — только через CSS-переменные (`--ink`, `--paper`, `--teal`…). Тема = набор переменных на `<html data-theme=… data-palette=…>`. Переключатель — в шапке, в меню «Оформление».
4. **Лупа и поиск.** Значок лупы в шапке на всех страницах. Открывает окно поиска по всему сайту (Pagefind, см. раздел 3) с горячей клавишей `/` или `Ctrl+K`. Ищет по-русски и по-арабски, с огласовками и без (нормализация как в `/dictionary`). Результаты сгруппированы: слова, задания, грамматика, статьи.
5. **Размер текста** (если заказчик под «лупой» имел в виду увеличение): в меню «Оформление» — «А− / А / А+», меняет базовый размер шрифта. Отдельно — размер арабского шрифта: студентам часто нужно крупнее.

### 14.2 Рекомендации Claude (по опыту учебных сайтов и приложений: Duolingo, Memrise, Anki, Madinah Arabic, LingQ и т. п.)
Внедрять по одной, с согласия заказчика:
- **Нижняя панель навигации на телефоне** (4–5 пунктов: Главная, Слова, Задания, Поиск, Я) вместо меню-«гамбургера»: на телефоне ею пользуются чаще всего.
- **«Продолжить с того места»** на главной для вошедших: последний набор, урок курса, сколько слов ждут повторения сегодня.
- **Дневная цель и серия дней** («5 дней подряд»), мягко и без наказаний. Для классов — видна учителю.
- **Карта курса**: уроки по порядку, у каждого прогресс (кружок с процентом). Понятно, что пройдено и что дальше.
- **«Хлебные крошки»** и кнопки «Предыдущее / Следующее задание» внутри курса.
- **Единая карточка задания** во всех списках: тип (иконка), уровень, примерное время, мой прогресс.
- **Озвучка** у каждого арабского слова (`speechSynthesis`) и **экранная арабская клавиатура** у полей ввода.
- **Всплывающая подсказка у слова**: нажал на арабское слово в тексте или упражнении → перевод, множественное число, «добавить в мои карточки».
- **«Мои карточки»**: ученик собирает свой набор из словаря и текстов.
- **Режим «только арабский»** (без переводов) для продвинутых и **огласовки вкл./выкл.** — тренировка чтения без харакатов.
- **Доступность**: видимый фокус, размеры кнопок не меньше 44 px, `prefers-reduced-motion`, понятные подписи для экранных дикторов.
- **Пустые состояния с действием** («Трудных слов нет → пройдите тест»), а не просто «пусто».

### 14.3 Как делать
- Сначала — **дизайн-токены** (`src/styles/tokens.css`): цвета для каждой палитры × светлая/тёмная, типографическая шкала, отступы, радиусы. Затем перевести все компоненты на токены: в компонентах не должно остаться «жёстких» цветов.
- Тема применяется **до отрисовки** (маленький inline-скрипт в `<head>`), чтобы не было вспышки светлой темы.
- Проверка: скриншоты Playwright каждой страницы в 4 палитрах × 2 режимах при ширине 360 и 1280; контраст AA (axe-core); нет горизонтальной прокрутки.
- Не делать одновременно с другим сеансом, который меняет те же файлы (например, этап 4). Сначала смёрджить этап 4, потом начинать дизайн, иначе будут конфликты.

## 15. Языки, ИИ, обратная связь (пожелания заказчика, 2026-10-13)

### 15.1 Узбекский (в первую очередь) и английский интерфейс — сделано 2026-10-14 (интерфейс; перевод материалов и `npm run translate` — впереди)
- Порядок: **uz** (латиница — официальная; кириллица позже, если попросят), затем **en**. Русский остаётся языком по умолчанию.
- Маршруты: `/uz/…`, `/en/…` (Astro i18n, `fallback` на `ru`). Переключатель языка в шапке и в подвале, выбор запоминается.
- Перевести: все строки интерфейса (`src/i18n/uz.ts`, `en.ts`) и описания материалов (поля `title_uz`, `description_uz`, `r_uz` у слов и т. д.). Арабский не переводится.
- **Перевод с помощью ИИ — не «на лету», а при добавлении материала.** Переводить каждую страницу при каждом открытии — медленно (секунды задержки), дорого (оплата за каждый показ), нестабильно (каждый раз чуть разный текст) и требует секретного ключа, который нельзя держать в статическом сайте. Правильная схема:
  1. Скрипт `npm run translate`: находит строки и материалы без `uz`/`en` и переводит их через **Claude API**. Терминология лингвистики задаётся глоссарием `src/i18n/glossary.json` (изафа = izofa, нисба…), его утверждает заказчик.
  2. GitHub Action запускает этот скрипт при каждом новом материале и создаёт PR с переводами. Заказчик (носитель узбекского) просматривает и мёрджит.
  3. Ключ Claude API хранится в **секретах GitHub** (`ANTHROPIC_API_KEY`), никогда не в коде и не в чате.
- Итог для пользователя тот же — сайт сразу на трёх языках. Но перевод проверен человеком и стоит копейки.

### 15.2 «Сообщить об ошибке» — обратная связь разработчику
- Кнопка на каждой странице (в подвале и рядом с каждым заданием): форма «Что не так?» + необязательный контакт. Автоматически прикладываются адрес страницы, язык, устройство, ключ задания или слова.
- Хранение: таблица `feedback` в Supabase (запись — через RPC с ограничением частоты; чтение — только администратор). Во вкладке «Администратор» панели — список с отметкой «исправлено».
- Уведомление заказчику в Telegram (бот + Edge Function; токен бота — в секретах Supabase). Включить, когда заказчик создаст бота через @BotFather.
- Отдельно — автоматический сбор ошибок JavaScript со страниц (только текст ошибки и адрес, без персональных данных) в ту же таблицу с типом `js_error`.

### 15.3 ИИ-помощник по языку и литературе
- Поле «Спросить у ИИ» (страница `/ask/` и кнопка «Спросить» рядом с грамматикой и словами).
- **Тематика — только научные вопросы по языкам и литературе**, прежде всего арабскому и узбекскому: грамматика, морфология, лексика, перевод, этимология, история литературы, стилистика, разбор текста. **Медицинские, политические, религиозно-правовые (фетвы) и прочие вопросы не обрабатываются**, ответ: «Этот помощник отвечает только на вопросы по языку и литературе».
- Устройство: Supabase Edge Function → Claude API. Ключ — в секретах Supabase.
  - Сначала короткая проверка темы дешёвой моделью: по теме или нет.
  - Затем ответ с системной инструкцией: роль преподавателя-филолога; отвечать на языке вопроса; арабский с огласовками; не выдумывать источники; при неуверенности так и говорить.
- **Честно о пределах:** ограничение темы через инструкции модели надёжно примерно, но не абсолютно. Пограничные вопросы («лексика медицинских текстов») — это вопросы о языке, их допускать.
- **Расходы и защита:**
  - только для вошедших (ученики классов и пользователи с email);
  - лимит, например 20 вопросов в день на человека и общий дневной лимит;
  - максимальная длина вопроса и ответа;
  - журнал вопросов (для улучшения и контроля злоупотреблений), срок хранения ограничен;
  - в Anthropic Console заказчик ставит месячный лимит расходов.
- Модель: дешёвая (уровень Haiku) для проверки темы, сильнее (уровень Sonnet) для ответов. Названия моделей сверить с docs.claude.com на момент работы.
- В «Конфиденциальности» добавить: вопросы к помощнику обрабатываются сервисом Anthropic; не вводить личные данные.

### 15.4 Узбекская орфография: поиск на imlo.uz
- Поле «Imlo: проверить написание» (на `/uz/`, в «Полезных ресурсах» и в поиске по сайту): ввёл слово → открывается страница слова на imlo.uz.
- Формат адреса (проверено 2026-10-13): `https://imlo.uz/word/<слово>`; несколько слов — через дефис; апостроф в oʻ, gʻ и разделительный — символ `‘` (U+2018), например `https://imlo.uz/word/no%E2%80%98g%E2%80%98aylar`. Открытого API у imlo.uz нет, поэтому только глубокая ссылка, без парсинга.
- Своё: нормализация ввода (все варианты апострофа `' ’ ` ʻ ‘` → `‘`, нижний регистр) и **транслитерация кириллица → латиница**, если слово введено кириллицей.

## 16. Задания от учителя (пожелание заказчика, 2026-10-13)

Сейчас учитель может только пользоваться готовыми материалами сайта. Материалы добавляются файлами в репозиторий, что доступно только администратору. На сайте несколько учителей, поэтому нужны две функции.

### 16.1 «Задания классу» — назначить готовый материал со сроком (сделать первым, просто и полезно)
- В панели учителя вкладка «Задания»:
  1. выбрать класс;
  2. выбрать материал (набор слов, викторина, тест, упражнение);
  3. указать срок и, при желании, условие: «выучить 50 слов», «викторина ≥ 70 %», «пройти 2 раза»;
  4. добавить комментарий.
- Ученик видит на главной и в `/me` блок «Задания от учителя»: срок, прогресс, отметка «выполнено» (засчитывается автоматически по данным базы).
- Учитель видит таблицу «ученики × задания»: ✓ выполнено, ◐ в процессе, ✗ не начато, просрочено.
- База: таблица `assignments` (class_id, activity, kind, due_at, goal jsonb, note, created_by) + RPC. Выполнение вычисляется из `card_state`, `card_tests`, `quiz_attempts`, отдельно не хранится.

### 16.2 Конструктор заданий учителя (свои наборы слов и викторины в браузере)
- В панели учителя вкладка «Мои материалы»:
  - **набор слов** — таблица «арабский / перевод / тема», с вставкой из Excel или Word (вставка таблицы через буфер);
  - **викторина** — вопрос, 4 варианта (первый правильный), пояснение, часть, время на вопрос.
  - Предпросмотр «как увидит ученик».
- Хранение — в Supabase (`teacher_materials`: owner, kind, data jsonb, status), а не в репозитории.
  - Статус «для моих классов»: сразу видно своим ученикам.
  - Статус «предложить на сайт»: администратор проверяет и одним нажатием публикует для всех.
- Отображение учеником: те же компоненты карточек и викторин, данные берутся из базы, а не из статического JSON. Прогресс и результаты пишутся так же, ключ активности — `t:<id>`.
- Проверка ввода:
  - в арабском поле должны быть арабские буквы;
  - предупреждение, если у слова нет огласовок;
  - не больше 300 слов в наборе и 60 вопросов в викторине.
- Импорт: загрузить JSON в формате `src/content/SCHEMA.md`. Учитель может подготовить его в чате Claude.

### Порядок
